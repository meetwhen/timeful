## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Record the agreed cross-device access design before implementation: a single "Continue on another device" flow uses a one-time, one-hour link and source-device approval. For signed-in users it transfers a normal platform session; for anonymous response owners it delegates browser-local event-scoped access without transferring Event Visitor Identity ownership. Signing in while that grant is active associates the source response-owning visitor identity with the Platform Identity.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Add ADR-010 for the shared source-confirmed transfer protocol: one-time, one-hour links initiate a pending target-device request; source confirmation issues either a platform session or event-scoped anonymous response-access grant.
2. Add separate FRs for anonymous response access transfer and authenticated platform-session transfer, plus a security QR for transfer validity and approval.
3. Amend FR-062 to preserve the source response-owning Event Visitor Identity when sign-in follows an approved response-access transfer; retain FR-001 as the existing many-responses-per-visitor requirement.
4. Add stable glossary terms and indexes; narrowly update ADR-009 to prevent transfer grants from being conflated with guest credentials or Event Visitor Identities.
5. Revise TASK-0071's plan and acceptance criteria to establish response-to-Event-Visitor-Identity ownership while deferring cross-device transfer behavior to a later implementation task.
6. Verify Markdown links and requirement/ADR structure. No automated test suite is required for this documentation-only task.
