## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-0077's no-split-sentence prototype only scans top-level text nodes of root-level paragraphs, so soft wraps adjacent to or inside inline links, code spans, and emphasis are never reported. The first TASK-0075 corpus pass left 93 such boundaries across 40 files (links dominate). This subtask reworks the rule to scan the paragraph's raw source lines with structural guards, extends fixtures to cover those boundary classes, and keeps lint:markdown unchanged. TASK-0075 then reruns normalization with the improved rule.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Rework eslint/markdown/no-split-sentence.js: scan the raw source text of root-level paragraphs line by line instead of only top-level text children. Keep hard-break exclusion (trailing backslash or two spaces), keep abbreviation/initialism/digit-period tail analysis on raw lines, report boundaries whose stripped tail lacks terminal punctuation.
2. Fix eligibility: join only when both trimmed sides are non-empty; never fix tails ending with a hyphen or pipes nor heads starting with a pipe; all other interior soft wraps in paragraphs render identically when joined with one space, including inside code spans.
3. Extend eslint/markdown/no-split-sentence.test.mjs with corpus-derived fixtures: tail ending before a link head, wrapped link label, wrapped inline code span, closing-paren continuation after a link, bold wrap, pipe-row report-only guard, hyphen-tail report-only guard, and a multi-boundary chain mixing inline structures; keep every existing fixture passing.
4. Update eslint/markdown/README.md detection and safe-fix sections for the new boundary model.
5. Validate npm run test:markdown-rules and npm run lint:markdown unchanged; hand back to TASK-0075 for corpus normalization with the improved rule.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Raw-source redesign rationale: per-child text scanning could not see boundaries where a line ends before a link/code/emphasis head starts, inside wrapped inline nodes, or at adjacent-child gaps. Scanning node.position raw source keeps the AST structural gates and makes those cases ordinary character-level boundary checks.

Fixable policy change: previous plain-character edge allowlist rejected nearly every real-world continuation; replaced by guards only for hyphen-ending tails and pipe edges, justified because joining an interior paragraph soft wrap with one space is render-equivalent under CommonMark whitespace handling, including inside code spans.

Fixture suite grew from 8 to 15 tests; the structural fixture dropped its three inline-structure stay-quiet blocks because reporting them is precisely the new intended behavior.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Reworked the no-split-sentence prototype to scan root-level paragraphs' raw source lines instead of only top-level text nodes, detecting soft wraps adjacent to and inside inline links, code spans, and emphasis while keeping every structural exclusion (headings, front matter, code, tables, blockquotes, list items including lazy continuations) and hard-break exclusion intact. Autofix joins only non-hyphen, non-pipe boundaries with a single space; hyphen tails and pipe fragments report without fixing. Added seven corpus-derived fixtures (link-head tail, wrapped link label, wrapped inline code span, closing-paren continuation, bold wrap, pipe report-only guard, mixed multi-boundary chain) and removed the three now-obsolete inline-structure exclusions from the structural fixture. Validation: npm run test:markdown-rules 15 of 15 fixtures; npm run lint:markdown unchanged with the rule off; no eslint.config.ts changes in this subtask. The improved rule auto-resolved 92 of the 93 residual TASK-0075 boundaries; the last one is the intentionally unfixed pipe fragment in QR-014.
