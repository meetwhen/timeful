## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Make the repository's sentences-per-line Markdown formatting safe for tables. The root `.prettierrc` uses `prettier-plugin-sentences-per-line`, whose formatter splits every sentence onto its own physical line even inside table cells. Because a Markdown table row must stay on a single physical line, `npm run format:markdown` currently destroys multi-sentence table rows rather than preserving them. This blocked the structural repair of `docs/requirements/quality/qr/QR-014.md` during TASK-0075: restored Response and Response measure rows were re-split by the formatter and then failed `npm run format:markdown:check`, so QR-014 was deliberately left as the corpus's only known no-split-sentence finding (disposition: "ignore qr-014 for now").

Desired outcome: a sentences-per-line formatting path that enforces one sentence per physical line in prose while leaving table structure fully intact — every table row remains exactly one physical line regardless of how many sentences a cell contains. Whether that comes from configuring the external plugin, replacing it with a local implementation, or another approach is decided by the implementer after researching the then-current options; TASK-0076 already ruled broadly that external sentence linters were unsafe for this repo, so prefer solutions verified against this corpus. Completing this unblocks the QR-014 structural repair and lets the parent task reach a zero-findings report-only scan.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Research findings (2026-08-26):

1. The external `prettier-plugin-sentences-per-line` never actually runs under the current CLI-based pipeline. Prettier's CLI (verified on locked 3.9.6 and floor 3.8.4, via `.prettierrc` plugins and explicit `--plugin`) imports the plugin module but resolves `.md` files with its built-in markdown parser/printer; instrumented runs show the plugin's `parse`/`preprocess` are never invoked. Via the JS API the same plugin works (last plugin defining a parser wins), so ordering is only controllable programmatically.
2. Consequence: `npm run format:markdown` currently performs no sentence splitting at all. The corpus splits from fe298f8e/TASK-0073 came from other mechanisms (ESLint autofix/manual passes).
3. The external plugin has no table awareness regardless: its walk inserts `sentenceBreak` nodes into every `sentence` node including those inside table cells, and it deletes the whitespace node when inserting (so naive post-hoc break removal would concatenate words like "approval.It").

Implementation plan:

1. Add local wrapper plugin `prettier/markdown/sentences-per-line.js` (ESM, mirrors `eslint/markdown/` layout): re-export upstream `options`, `parsers`, `printers`; wrap only `printers.mdast.preprocess` — run the upstream preprocess verbatim (keeps abbreviation/boundary logic), then walk the AST and replace every `sentenceBreak` node inside `table`/`tableRow`/`tableCell` ancestry with a whitespace node (single space), restoring exact single-row cell content while leaving prose breaks untouched.
2. Rewrite `scripts/markdown.mjs` format/format:check to call Prettier programmatically (`prettier.resolveConfig` + `prettier.format` per tracked file, explicit `plugins: [localPlugin]` so built-in shadowing cannot occur). Keep command names, git-scoped file list, exclusions, eslint lint path, and CLI-like output/exit codes (check exits 1 listing unformatted files).
3. Point root `.prettierrc` plugins at the local plugin so API-based consumers (editors) get table-safe behavior too.
4. Tests in `prettier/markdown/sentences-per-line.test.mjs` (vitest) + new npm script `test:markdown-format`: prose splitting, multi-sentence table row integrity, QR-014-style round-trip stability, idempotency, abbreviation passthrough.
5. Validate: full-corpus `format:markdown` must produce zero diffs (corpus is already one-sentence-per-line; tables were previously stable because the plugin was inert), then `format:markdown:check`, `lint:markdown`, `test:markdown-rules`, `test:markdown-format`, `git diff --check`.

Out of scope: repairing `docs/requirements/quality/qr/QR-014.md` itself — that belongs to parent TASK-0075 (criteria #2/#4) and becomes possible once this lands.

Follow-up plan (2026-08-26): 1. Restore QR-014's Response and Response measure as complete single-line table rows without changing wording. 2. Replace the stale QR-014-style synthetic case with coverage that formats the exact repaired QR-014 document and verifies table-row integrity and idempotency. 3. Extend Markdown CI path filters to include the local formatter implementation and tests. 4. Run formatter, formatter check, Markdown lint, formatter and rule tests, the report-only no-split scan, git diff --check, and graphify update.

Follow-up adjustment (2026-08-26): keep the QR-014 formatter regression fixture self-contained rather than reading the requirement file. The fixture will retain the exact repaired QR-014 Response and Response measure wording and a valid eight-row table, while formatter and CI checks cover the repository document independently.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented the approved local wrapper at `prettier/markdown/sentences-per-line.js` and changed `scripts/markdown.mjs` format/check to use the Prettier JavaScript API with an explicit local plugin. This bypasses the verified CLI built-in-printer shadowing behavior.

The wrapper runs the upstream preprocess unchanged, then replaces only table-descendant `sentenceBreak` nodes with whitespace. This is necessary because upstream removes the whitespace when adding each break; deleting a break directly would concatenate adjacent words.

Objective verification: `npm run format:markdown` made no corpus changes; `npm run format:markdown:check` and `npm run lint:markdown` passed; `npm run test:markdown-rules` passed 15 tests; `npm run test:markdown-format` passed 4 tests covering prose, tables, QR-014-style rows, round-trip stability, and custom abbreviations; `git diff --check` passed. `graphify update .` completed with optional parser/dependency warnings.
