## Implementation Plan

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Fixture evidence: with textlint 15.8.0, idiomatic-lines 1.2.0, and node-types filtered as ListItem, correctly indented wrapped unordered, ordered, and nested list items produced no diagnostics and remained byte-for-byte unchanged after --fix. Wrapped ordinary prose and two prose sentences on a line produced the expected two diagnostics and --fix changed only those prose lines.

Important limitation: an unordered list continuation without its required indentation was reported by idiomatic-lines. The ListItem filter is therefore not a universal mitigation for list-like/lazy-continuation input. No repository dependencies, configuration, or Markdown files were changed.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Tested an isolated configuration with textlint 15.8.0, textlint-rule-idiomatic-lines 1.2.0, and textlint-filter-rule-node-types configured for ListItem. Correctly indented wrapped unordered, ordered, and nested items were ignored and unchanged by --fix; ordinary prose still produced the expected two diagnostics and was correctly fixed.

The mitigation is not safe for general adoption: an unordered list with an unindented continuation was still reported, so filtering ListItem does not reliably cover all list-like/lazy-continuation inputs. No repository dependencies, configuration, or Markdown files changed.

Validation: isolated fixture lint; isolated fixture --fix --dry-run; isolated fixture --fix with verified output.
<!-- SECTION:FINAL_SUMMARY:END -->
