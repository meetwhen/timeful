## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Follow-up styling cleanup in the TASK-0123 family: remove shadows from the shared neutral form-field surfaces so they read as flat outlined controls, complementing the parent task's neutral outline token conversion.

Durable facts (verified 2026-08-31):
- frontend/src/index.css `.timeful-solo-field .v-field` carries `filter: drop-shadow(0 0.5px 2px rgba(0, 0, 0, 0.1)) !important` and `box-shadow: inset 0 -1px 0 0 rgba(0, 0, 0, 0.1) !important`. The box-shadow declaration also suppresses Vuetify's default solo-variant elevation, so removal must become `box-shadow: none !important`, not deletion.
- frontend/src/components/DatePicker.vue puts `tw-drop-shadow` on the v-date-picker; DatePicker is used only by NewEvent.vue and NewSignUp.vue.
- `.timeful-solo-field` is an app-wide shared class (NewEvent, NewSignUp, SignIn, SignInDialog, GuestDialog, RespondentsList, TimezoneSelector, WorkingHoursToggle, BufferTimeSwitch, EventItem, EmailInput, SignUpForSlotDialog, AppleCredentials, ICSCredentials, NewGroup); the shadow removal is intentionally scoped at the shared class level so all forms get the same flat look (confirmed with the user 2026-08-31).

Decisions recorded:
- Elevated CTA shadows stay: `.timeful-elevated-button*` and `.timeful-switch` track shadows in index.css are out of scope (user decision 2026-08-31).
- NewEvent/NewSignUp compact switches are already flat via ScheduleOverlapCompactSwitch.css `box-shadow: none` rules; no change needed there.
- Sequencing: implement together with or after the parent task's solo-field border conversion; removing the shadow while the border is still #4f4f4f1f leaves fields nearly invisible.
