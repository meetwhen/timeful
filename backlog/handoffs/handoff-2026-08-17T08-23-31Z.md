## Session Objective

Change the timezone behavior of the frontend's "new event" creation forms so that: (1) there is no timezone reset button, (2) the event timezone initializes from the browser timezone rather than a global stored timezone, and (3) the timezone button width is fixed. Completed; all required checks pass and the changes are staged but uncommitted.

## Motivation And Impact

The new event forms (`NewEvent`, `NewSignUp`, `NewGroup`) previously initialized their timezone from a global `localStorage["timezone"]` value shared with the event page's "shown in" timezone (`ScheduleOverlap.vue`), and rendered a reset (Undo) button once the timezone deviated from the default. A user picking a "shown in" timezone elsewhere would pre-fill new forms with that value instead of the browser timezone. The forms now always start from the browser timezone, never read or write the global key, show no reset button, and the `NewEvent` timezone button keeps a fixed 112px width so it does not resize as the selected timezone changes.

## Completed Work

- `useOwnedTimezone.ts`: added a `persist` option (default `true`). With `persist: false` the timezone initializes from the browser timezone (ignoring `resolveSavedTimezoneSelection`), `modified` starts `false`, and `setTimezone`/`resetTimezone` no longer read or write storage. Default behavior for existing consumers (e.g. `ScheduleOverlap.vue`) is unchanged.
- `useEventEditorState.ts`: `useOwnedTimezone({ persist: false })`, affecting `NewEvent` and `NewSignUp`.
- `NewGroup.vue`: `useOwnedTimezone({ persist: false })`.
- `TimezoneSelector.vue`: added a `showReset` prop (default `true`); both reset buttons render only when `showReset && modified`.
- `NewEvent.vue`: timezone selector now uses `fixed-width` (112px via existing `tw-w-28` mechanism, matching the `ToolRow.vue` compact pattern) plus `:show-reset="false"`; removed the `:modified`/`@reset` bindings and the now-unused `timezoneModified`/`resetTimezone` destructures.
- `NewSignUp.vue` and `NewGroup.vue`: `:show-reset="false"`, removed `:modified`/`@reset` and unused destructures.

## Important Decisions

- Scope is all three creation forms (`NewEvent`, `NewSignUp`, `NewGroup`), confirmed by the user.
- The fixed width is 112px, reusing the existing `fixed-width` mechanism (`tw-w-28`), confirmed by the user.
- Non-persisting mode is implemented as a `persist: false` option on the shared `useOwnedTimezone` composable rather than a new composable, keeping the existing API for `ScheduleOverlap.vue` intact.
- Reset-button removal is done via an explicit `showReset` prop on `TimezoneSelector.vue` rather than by omitting the `modified` prop, so the behavior is explicit and testable.

## Decision Rationale

- Reusing `fixed-width` keeps the button consistent with the event-page compact mobile toolbar (`ToolRow.vue`), which already fixes the width at 112px so the reset button fits without resizing.
- `persist: false` on the shared composable avoids a parallel timezone implementation and keeps `ScheduleOverlap.vue`'s persisted "shown in" behavior unchanged.
