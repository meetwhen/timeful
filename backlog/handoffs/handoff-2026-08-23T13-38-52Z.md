## Important Decisions

### PostgreSQL Coexistence

- Phase one is a compatibility migration: PostgreSQL owns only newly created,
  eligible anonymous timed and dates-only polls. MongoDB remains authoritative
  for legacy events, authenticated creation, groups, signup forms, and
  account-backed features.
- Each event aggregate has exactly one database authority. There are no dual
  writes, import-on-read operations, split aggregates, or migration of an
  existing PostgreSQL event back to MongoDB.
- PostgreSQL event IDs are `p_` plus a 26-character ULID; short IDs are `p_`
  plus eight Crockford characters. PostgreSQL uses hidden UUIDv7 event and
  response primary keys. Classify `p_` IDs before legacy short-ID/ObjectID
  logic.
- `POSTGRES_ANONYMOUS_EVENT_CREATION_ENABLED` controls only future creation.
  When disabled, all anonymous creation goes to MongoDB; existing PostgreSQL
  events remain readable and mutable.
- Preserve normal observable behavior first. Unsupported or noncanonical
  anonymous creation falls back to Mongo when PostgreSQL creation is enabled;
  unsupported edits to an existing PostgreSQL event return a stable error.
- Preserve phase-one guest behavior, including 24-hex guest IDs, plaintext
  recoverable tokens, tokenless open mutation credentials, map keys, guest-name
  normalization, response cardinality, public anonymous metadata edits, and
  public selected-schedule mutations. Hash-only token storage and new response
  capabilities are future work.
- PostgreSQL anonymous ownership serializes as the existing zero ObjectID
  sentinel. Signed-in responses retain Mongo user IDs as external strings, but
  PostgreSQL events do not appear in `/api/user/events` or the dashboard in
  phase one. Plugin `get-slots`/`set-slots` payload shapes must not change.
- Preserve millisecond instants, dates-only instants, ordering/duplicates,
  permissive response slots, timed local strings, recurrence anchoring, and
  selected-schedule semantics. Use transactions and constraints without
  deliberately reproducing internal Mongo corruption or races.
- PostgreSQL is PostgreSQL 18.6, using the official Bookworm image and a
  reviewed digest. Use `pgx/v5`, Goose, separate bootstrap, migrator,
  application, and backup roles, a migration service before the app,
  dual-database readiness, and fresh `timeful-test-*` PostgreSQL test databases.
  Backup/recovery automation was deliberately deferred from phase one.
- Normal browser E2E continues to create Mongo events. PostgreSQL anonymous
  creation coverage is opt-in through
  `E2E_POSTGRES_ANONYMOUS_EVENT_CREATION_ENABLED=true`, forwarded to the test
  stack as `POSTGRES_ANONYMOUS_EVENT_CREATION_ENABLED`.

## Decision Rationale

- PostgreSQL compatibility and narrow source dispatch minimize regression risk
  while permitting atomic relational storage for new anonymous polls. The
  2026-08-16 compatibility-first decisions supersede the earlier normalized
  schema, immediate token-hashing, strict field rejection, derived-count, and
  phase-one backup proposals.
- Browser-timezone creation state must not be coupled to the persisted
  event-page display timezone. Reusing the existing composable avoids a second
  timezone implementation.
- The shared edge network lets independently deployed Caddy and Stalwart
  stacks resolve each other without merging their lifecycle or environment.
- Canonical requirements remain small and evidence-based so they do not turn
  implementation notes or unresolved product questions into requirements.

## Constraints And Assumptions

### PostgreSQL

- `server/routes/events.go` is directly Mongo-coupled. Do not begin by broadly
  rewriting it into a generic repository; prefer a source classifier, route
  wrappers, existing Mongo handlers, and narrow PostgreSQL compatibility
  handlers.
- Keep PostgreSQL rows separate from HTTP DTOs and Mongo BSON models. Current
  models cannot represent namespaced PostgreSQL IDs.
- Namespaced IDs must be path-safe. The frontend strips dots and does not
  consistently URL-encode route IDs.
- Frontend ownership remains keyed by long event ID. Do not rewrite existing
  IDs. OAuth `eventsToLink` must ignore namespaced IDs while retaining Mongo
  ObjectID linking.
- Account adoption, dashboard inclusion, folders, archive/delete/duplicate,
  groups, signup, reminders, notifications, blind availability, email
  collection, remote import, and authorization redesign remain out of scope.
- Creator analytics inclusion was previously selected as a narrow cross-store
  need but required confirmation before implementation.
- Public anonymous metadata edits intentionally preserve observed behavior, but
  conflict with ADR-010. Reconcile the ADR or its status before treating that
  behavior as settled policy.
- PostgreSQL backup/disaster-recovery automation, off-host replication, restore
  drills, RPO, and RTO were deferred and remain an accepted operational risk.
