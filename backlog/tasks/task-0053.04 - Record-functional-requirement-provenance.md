## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Make the origin of every functional requirement auditable through source-neutral metadata while keeping each requirement independently normative and readable without its source.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A source-neutral provenance schema is documented for functional requirements
- [ ] #2 Every functional requirement records its researched provenance or an explicit no-recoverable-source classification
- [ ] #3 Requirement statements remain self-contained and do not depend on provenance links for interpretation
- [ ] #4 Architectural-decision provenance is used only when an ADR actually originated the requirement
- [ ] #5 The requirements index and metadata are structurally validated
<!-- AC:END -->
