## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Third delivery subtask of TASK-0071, depends on TASK-0071.05. Wire PostgreSQL routes to the identity foundation: event creation issues and binds an owner Event Visitor Identity, event fetch exposes public identifiers with blind-availability filtering, response CRUD authorizes via source EVCC or an associated Platform Identity session with an explicit selected-response contract for multiple responses per Event Visitor Identity, and sign-in associates browser Event Visitor Identities with the session's Platform Identity. Owner-power enforcement (settings edits, archive, delete) is deliberately out of scope and tracked in a follow-up task.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 PostgreSQL event creation issues the owner Event Visitor Identity and EVCC, returns the public eventVisitorId, and binds the owner Event Visitor Identity on the event for blind-availability visibility; no Event Owner Edit Token or settings authorization is implemented in this subtask
- [ ] #2 PostgreSQL event fetch exposes the browser eventVisitorId and opaque response public_ids; blind-availability reads expose a non-owner only responses the visitor is authorized to manage with no other-response counts, while the owner views all responses
- [ ] #3 PostgreSQL response create, update, and delete authorize through a source EVCC or an authenticated session whose Platform Identity is associated with the owning Event Visitor Identity, and never treat a raw eventVisitorId or Platform Identity value supplied as a credential as authorization (QR-003)
- [ ] #4 PostgreSQL response APIs support multiple responses per Event Visitor Identity with an explicit selected-response creation, edit, and deletion contract and preserve transactional num_responses updates
- [ ] #5 Sign-in associates the current browser Event Visitor Identities with the session visitor's private Platform Identity (find-or-create) without MongoDB queries or migration (FR-079)
- [ ] #6 MongoDB request shapes, behavior, and credentials are byte-identical to before
- [ ] #7 Route and frontend regression coverage verifies PostgreSQL identity behavior, blind filtering, and MongoDB non-regression (TASK-0071 AC #5 through AC #9, AC #11)
<!-- AC:END -->
