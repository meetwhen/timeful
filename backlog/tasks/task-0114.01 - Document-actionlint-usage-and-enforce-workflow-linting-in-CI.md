## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Follow-up to TASK-0114, which pinned all GitHub-hosted action references to full-length SHAs. Two gaps remain: (1) workflow validation currently relies on ad-hoc local actionlint runs (previously via Docker) with no documented local entry point and no CI enforcement, even though actionlint is now available on PATH in this environment; (2) the GitHub repository setting "require actions to be pinned to full-length commit SHA" (Settings > Actions > General) is the enforcement backstop for the pinning work and is not recorded anywhere in-repo.

Outcome: a docs/ci.md guide documents local actionlint usage, CI enforcement, and the recommended repo setting; markdown-ci.yml runs actionlint on .github/workflows/*.yml so workflow edits are validated on push/PR.

Constraints: do not change the semantics of existing markdown-ci jobs beyond adding the actionlint step; keep the actionlint invocation simple and deterministic (no floating network fetches of scripts if avoidable); reuse the pinned-SHA conventions from TASK-0114 for any new action references; documentation must follow docs/AGENTS.md authoring rules.
<!-- SECTION:DESCRIPTION:END -->
