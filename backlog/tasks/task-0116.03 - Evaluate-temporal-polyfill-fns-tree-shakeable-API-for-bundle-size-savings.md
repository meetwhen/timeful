## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Outcome

Reduce the production bundle cost of the Temporal runtime beyond what the 1.x upgrade alone provides, by evaluating and, where measurement justifies it, adopting the `temporal-polyfill/fns` tree-shakeable entrypoint or other bundle-size work. This follow-up was explicitly deferred from TASK-0116.

## Context

TASK-0116 deliberately kept the ponyfill entrypoint (`import { Temporal } from "temporal-polyfill"` in roughly 100 files) and deferred `/fns` adoption and bundle-size work. temporal-polyfill 1.x costs 19.5 kB min+gzip (23.4 kB for `/full/` entrypoints).

## Constraints

- Decide with measurements, not speculative refactoring: record the baseline first, then measure the candidate improvement and adopt only if the saving is meaningful.
- No runtime behavior change; preserve ADR-004's single Temporal runtime model with native delegation.
- Whether a central re-export module is warranted as part of an `/fns` migration is an implementation decision for this task; TASK-0116 only deferred it from the upgrade itself.
- Re-verify the latest package entrypoint docs at execution.
