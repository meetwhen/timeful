## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
In the reworked "What times might work?" one-row layout (NewEvent.vue and NewSignUp.vue), the selected-time text inside the start/end range select chips sits slightly above vertical center of the 32px chip instead of being centered.

Context from TASK-0124 browser verification: the 32px chip height is achieved with `.time-range-row .v-input.time-range-select .v-field { --v-field-input-padding-top: 0px; --v-field-input-padding-bottom: 4px; }`, so the asymmetric field padding is the likely reason the input text renders high. Fix the vertical centering with a layout-based fix (balanced padding or an equivalent explicit centering approach) without changing the 32px chip height, the ~40px dropdown item height, or the row layout. Also verify the "to" separator stays centered relative to the chips.

Scope is limited to the time-range row in frontend/src/components/NewEvent.vue and frontend/src/components/NewSignUp.vue.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Root cause (verified in Firefox devtools): Vuetify's `.v-input--density-default .v-field--variant-solo { --v-input-control-height: 56px; --v-field-padding-bottom: 4px }` matches the `.v-field` element directly; the old root-level override only set an inherited value, and inherited values always lose to direct rules - that is why the 32px never applied. Same mechanism killed `--v-field-padding-start: 8px` (`.v-field` defines 16px directly).

The -2px in `calc(var(--time-range-chip-height) - 2px)` is box arithmetic, not a hack: the visible chip is the `.v-field` box plus the two 1px borders from the shared `.timeful-solo-field` style; the knob represents the outer (visible) chip height.

Height knob semantics: `.v-field__input` min-height = max(control-height, 1.5rem + padT + padB); with balanced 0/0 padding the knob controls height cleanly down to ~26px (1.5rem content floor + borders). Text centering relies on Vuetify's flex `align-items: center` inside the unpadded content box.

Per-chip control verified in browser: setting `--time-range-chip-height: 40px` inline on one select renders that chip at 40px (text still centered) without affecting the other chip.

AC adjusted with user approval (2026-09-01): 58px knob-based height replaces the 32px/TimeFormatToggle requirement; the 32px target never actually rendered (chip was already 58px in the browser).

NewSignUp browser verification deferred to TASK-0124.03 (sign-up tab not reachable signed out); the component and its CSS are shared verbatim between both forms.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
## Fix

The selected-time text sat high because the chip-height/padding overrides were set on the `.v-input` root, where they only produce *inherited* custom-property values. Vuetify re-pins `--v-input-control-height: 56px` directly on the `.v-field` element via `.v-input--density-default .v-field--variant-solo`, and any direct rule beats an inherited value — so the 32px override never took effect (and `--v-field-padding-start: 8px` was silently dead too, rendering 16px). Separately, the asymmetric `--v-field-input-padding-*` (0px top / 4px bottom) made Vuetify's `align-items: center` center the text in a 28px content box, 2px above chip center.

## Changes (frontend/src/components/TimeRangePicker.vue)

- Single height knob: `--time-range-chip-height: 58px` on `.time-range-picker` (the approved natural chip height).
- Overrides now target `.v-field` (the element Vuetify pins its density rules on), with `(0,3,0)` specificity beating `(0,2,0)` density rules: `--v-input-control-height: calc(var(--time-range-chip-height) - 2px)` (minus the two 1px `.timeful-solo-field` borders), `min-height: var(--time-range-chip-height)`, balanced `--v-field-input-padding-*: 0px`, and the previously dead `--v-field-padding-start: 8px` moved here.
- Separator now follows the knob (`height: var(--time-range-chip-height)`), keeping it centered at any chip height.
- Per-chip control works by setting the var on one select (e.g. inline style or a CSS rule); no component API change needed.

## Verification (Firefox, Vite dev server 4173)

- NewEvent dialog: both chips 58px, text center offset 0 (measured on `.v-select__selection`), separator center offset 0, `padding-inline-start` 8px.
- Per-chip proof: `--time-range-chip-height: 40px` on the end select only → end chip 40px (still centered), start chip unaffected, removal restores 58px.
- Dropdown items 40px (user-confirmed in devtools; CSS assertion keeps `min-height: 40px`).
- NewSignUp browser check deferred: signed-out create dialog shows no sign-up tab (TASK-0124.03 blocker). NewSignUp renders the identical shared component, and its unit tests assert the TimeRangePicker usage.
