## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Enable the isolated test stack to exercise calendar integration flows end to end without live provider access.

The current isolated stack cannot persist calendar credentials because ENCRYPTION_KEY is empty, so every add flow fails GCM encryption. Provide a valid 32-byte ENCRYPTION_KEY to the test server and route-test services.

Token refresh and non-ICS sub-calendar loading call hard-coded external provider endpoints. Add a test-only, env-overridable OAuth token endpoint (defaulting to the real provider URLs) and a mock provider reachable from server-test, so an expired OAuth2 account can refresh and a non-ICS account with sub-calendars can be loaded without real network access.

Keep all changes test-scoped and non-production: production behavior must remain unchanged when the override is unset. Update the environment contract and e2e guidance to document the test-only calendar configuration.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The isolated test stack provides a valid 32-byte ENCRYPTION_KEY so calendar credential writes and reads succeed in server-test and server-route-test.
- [ ] #2 An OAuth token endpoint override lets the running test server reach a mock token provider while production keeps the real provider endpoints when the override is unset.
- [ ] #3 A non-ICS calendar account with sub-calendars can be loaded and returned by GET /user/calendars in the isolated stack without real provider network access.
- [ ] #4 Environment and e2e documentation record the test-only calendar configuration and that it must never be enabled in production.
