## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Account references are denormalized as TEXT columns keyed by platform_identities.external_user_id: account_user_id columns in event responses, attendees, signup responses, folders and folder events, availability groups, and daily user logs; postgres_events.owner_external_id; access_transfers.external_user_id; account_deletion_tombstones.external_user_id. Consolidate them onto native uuid columns referencing platform_identities.id, backfill existing rows once, then remove external_user_id and the legacy TEXT columns. event_visitor_identities.platform_identity_id and postgres_events.owner_platform_identity_id already exist and become the canonical references. Tombstones must survive identity deletion and therefore carry the uuid without a foreign key. This subtask ships with the backend boundary subtask.

Constraints:
- The backfill runs in a single guarded migration transaction, is idempotent on re-run, and refuses a destructive down migration without a reviewed data-preserving path.
- Drop platform_identities.external_user_id last, after every dependent column is consolidated and the mapping verified.
- Repository and service code must not query dropped columns; repository tests use the isolated test stack.
- Use native uuid columns and the existing uuidv7() defaults; do not add new TEXT identifier columns.
<!-- SECTION:DESCRIPTION:END -->
