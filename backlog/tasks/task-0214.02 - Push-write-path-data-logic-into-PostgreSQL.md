## Description

# Goal

Push write-path loops and read-modify-write sequences into set-based PostgreSQL statements without schema changes.

# Scope

- `server/postgres/attendees.go:41-59`, `server/routes/postgres_group.go:208-257`, `server/routes/postgres_event_routes.go:1121-1135`: batch account resolution and attendee writes with `unnest` and `INSERT ... SELECT ... LEFT JOIN LATERAL`; preserve owner protections, decline state, and email ordering.
- `server/accounts/calendar.go:137-168`: replace the per-sub-calendar upsert, re-read, and per-row delete with one upsert from `unnest` and one `DELETE ... <> ALL(...)`.
- `server/postgres/repository.go:165-179`: replace full-row `UpdateEvent` writes after `num_responses` mutation at `server/routes/postgres_event_routes.go:826,854` and `server/routes/postgres_group.go:235,561,630` with targeted `num_responses = num_responses +- 1` updates.
- `server/routes/postgres_owner.go:186-204`: set the archive/delete flag with a targeted UPDATE.
- `server/postgres/folders.go:93-123`: replace the dynamically assembled SET list with a static `COALESCE` update.
- `server/postgres/identities.go:115-121`: make `LockEvent` scan the locked row in one statement.

# Constraints

- Keep the event row lock and transaction boundaries that serialize response mutations.
- Preserve `23505` to duplicate-name error mapping and `pgx.ErrNoRows` not-found behavior.
- SQL stays in `server/postgres/`.
- No schema changes in this subtask.

# Verification

- Run the backend route and repository suites with the isolated test overlay in `compose.test.yaml`.
- Add or update tests covering the batched write paths before or with the fix.
