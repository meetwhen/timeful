## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
# Goal

Replace the `event_signup_responses.block_ids TEXT[]` document-array shape with a relational join table and set-based capacity and membership logic.

# Scope

- Add a goose migration in `server/migrations/` creating `event_signup_response_blocks` with foreign keys to `event_signup_responses` and `event_signup_blocks`, a unique constraint on `(response_id, block_id)`, a `position` column that preserves the response's claimed-block order, and an index that supports grouped capacity counts and block cascades (for example `(block_id, response_id)`).
- Backfill the new table from existing `block_ids` values in array order (using `WITH ORDINALITY` for `position`), deduplicating entries and skipping values that do not name a same-event block, then drop `event_signup_responses.block_ids`.
- Rewrite the response membership paths in `server/postgres/signup.go`: `CreateSignupResponse`, `UpdateSignupResponse`, `GetSignupResponseByPublicID`, `ListSignupResponses`, `signupResponseColumns`, and `scanSignupResponse` read and write the join table, and every read aggregates memberships back into `BlockIDs` ordered by `position`.
- Rewrite `server/postgres/signup.go:350-398` `reserveSignupCapacity` to use a grouped JOIN against the join table with the excluded response applied in the query, and to still report `ErrSignupBlockNotFound` for any requested block that is missing or belongs to another event.
- Rewrite `server/postgres/signup.go:111-189` `ReplaceSignupBlocks` to use set-based upsert and delete statements, preserving `pgx.ErrNoRows` when a supplied block ID does not belong to the event.
- Keep the trimming, empty removal, and first-seen dedupe in `normalizeSignupBlockIDs`; the unique constraint is the backstop.

# Constraints

- The capacity check must remain inside the transaction that holds the event row lock.
- Preserve `ErrSignupBlockNotFound` (400 `signup-block-not-found`) and `ErrSignupCapacityExceeded` (409 `signup-slot-full`) semantics, including for non-canonical or foreign block identifiers; invalid UUID text must not surface as a SQL cast error.
- Preserve the wire `BlockIDs` order observed by clients. A position column is required, not optional.
- Specify `ON DELETE CASCADE` on both join-table foreign keys. Decide and record whether removing a block still bumps `event_signup_responses.updated_at`, which the current detach path does and a cascade alone does not.
- Typed UUID binds and the remaining `public_id::text` casts in `server/postgres/signup.go` belong to TASK-0214.04, which depends on this task; keep the existing cast behavior in statements this task does not rewrite.
- The baseline migration is immutable; add a new migration instead.
- The new migration must stay compatible with the temp-table migration harness at `server/postgres/migration_helpers_test.go:57-59`.

# Verification

- Apply migrations against the isolated test stack and run the repository and route signup test suites under `compose.test.yaml`.
- Add migration and repository regression tests for capacity, duplicate and empty block IDs, foreign block IDs, and multi-block ordering round-trip.
- Update the existing tests that read `event_signup_responses.block_ids` directly, such as `server/postgres/signup_test.go:355`.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Corrected on 2026-09-13 after a code audit of the original scope.

Key corrections:

- The original scope rewrote only reserveSignupCapacity and ReplaceSignupBlocks; replacing the column also requires CreateSignupResponse, UpdateSignupResponse, GetSignupResponseByPublicID, ListSignupResponses, signupResponseColumns, and scanSignupResponse.
- Position is required to preserve the wire BlockIDs order; the original "position column if required" hedge conflicted with acceptance criterion #5. The backfill needs WITH ORDINALITY.
- The migration must drop block_ids after backfill, deduplicate and skip dangling or invalid stored IDs, specify ON DELETE CASCADE for both foreign keys, and add an index on block_id for grouped capacity counts and cascades.
- Membership validation cannot move to the boundary: a join-table foreign key proves a block exists but not that it belongs to the response's event, so the event-scoped capacity query remains the validator and must still surface ErrSignupBlockNotFound.
- UUID validation before SQL casts belongs to TASK-0214.04, which now depends on this task. Non-canonical block identifiers must keep mapping to ErrSignupBlockNotFound (400 signup-block-not-found), not pgx.ErrNoRows or a 22P02 error.
- ReplaceSignupBlocks' current detach path also bumps event_signup_responses.updated_at; a cascade does not, and the task must record the decision.
- Existing tests that query block_ids directly and the temp-table migration harness must be updated as part of this task.
