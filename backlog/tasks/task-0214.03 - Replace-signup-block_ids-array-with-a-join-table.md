## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
# Goal

Replace the `event_signup_responses.block_ids TEXT[]` document-array shape with a relational join table and set-based capacity and replacement logic.

# Scope

- Add a goose migration in `server/migrations/` creating `event_signup_response_blocks` with foreign keys to `event_signup_responses` and `event_signup_blocks`, a unique constraint on `(response_id, block_id)`, and a position column if required to preserve order.
- Backfill the new table from existing `block_ids` values as part of the migration.
- Rewrite `server/postgres/signup.go:350-398` `reserveSignupCapacity` to use a grouped JOIN with the exclusion applied in the query.
- Rewrite `server/postgres/signup.go:111-189` `ReplaceSignupBlocks` to use set-based upsert and delete statements.
- Keep membership validation and duplicate stripping at the boundary, with UUID validation before SQL casts.

# Constraints

- The capacity check must remain inside the transaction that holds the event row lock.
- Preserve `ErrSignupBlockNotFound` and `ErrSignupCapacityExceeded` semantics.
- Preserve the wire `BlockIDs` order observed by clients.
- The baseline migration is immutable; add a new migration instead.

# Verification

- Apply migrations against the isolated test stack and run the repository and route signup test suites under `compose.test.yaml`.
- Add migration and repository regression tests for capacity, duplicate block IDs, and replacement ordering.
