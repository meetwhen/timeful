# ADR-010: Source-Confirmed Cross-Device Access Transfers

## Context

Visitors need a quick way to continue on another browser without treating a
copied URL as a credential, changing the owner of an
[Availability Response](../../../terminology/glossary.md#availability-response), or exposing other respondents in
[Blind Availability](../../../terminology/glossary.md#blind-availability). The same user-facing action must support an authenticated
[Platform Identity](../../../terminology/glossary.md#platform-identity), an ordinary anonymous
[Event Guest](../../../terminology/glossary.md#event-guest), and an anonymous
[Event Owner](../../../terminology/glossary.md#event-owner).

## Considered Options

- Make the copied link a direct bearer credential that immediately signs in or
  grants authority.
- Deliver an email-only recovery link.
- Transfer response ownership to the target browser's [Event Visitor Identity](../../../terminology/glossary.md#event-visitor-identity).
- Require source-device confirmation before granting target-device access.

## Decision

The frontend presents one `Continue on another device` action for PostgreSQL
events. Its copied link starts a pending
[Cross-Device Access Transfer](../../../terminology/glossary.md#cross-device-access-transfer) that expires five minutes after creation.
When the target browser opens the link, it displays a matching code. The source
browser must approve that exact code during the five-minute window. Opening the
link alone grants no authority; approval consumes the pending transfer.

For a signed-in source, approval issues a normal authenticated session for the
same [Platform Identity](../../../terminology/glossary.md#platform-identity) on the target browser. For an anonymous PostgreSQL source,
the source proves its [Event Visitor Control Credential](../../../terminology/glossary.md#event-visitor-control-credential-evcc) before initiating the transfer. Approval issues the target a distinct
[Granted Event Visitor Control Credential](../../../terminology/glossary.md#granted-event-visitor-control-credential-granted-evcc), scoped to the source
[Event Visitor Identity](../../../terminology/glossary.md#event-visitor-identity) and event. It delegates the source role without disclosing the source credential or transferring response, event, or Event Visitor Identity ownership.

An ordinary anonymous [Event Guest](../../../terminology/glossary.md#event-guest)'s
[Granted Event Visitor Control Credential](../../../terminology/glossary.md#granted-event-visitor-control-credential-granted-evcc) authorizes the source visitor's responses. An anonymous
[Event Owner](../../../terminology/glossary.md#event-owner) must additionally prove the
[Event Owner Edit Token](../../../terminology/glossary.md#event-owner-edit-token); that Granted EVCC preserves all event-owner powers, including settings, response visibility, archive, and deletion. A Granted EVCC has no fixed server-side expiry, remains browser-local, and is revocable by the source. If a target browser with an active Granted EVCC signs in, the system must obtain explicit confirmation before associating the source Event Visitor Identity with that Platform Identity for durable recovery.

This decision does not change MongoDB credentials, persistence, or transfer
behavior.

Email delivery is deferred. It may later carry the same pending transfer link,
but it must not introduce a separate authorization model.

## Consequences

- A copied link alone cannot sign in a browser or authorize a response.
- Matching-code approval prevents the first person to open a copied link from
  binding the transfer to their browser.
- The source can immediately remove delegated authority by revoking a Granted
  EVCC, even though the target browser retains it until its data is cleared.
- The source browser must remain available while approving the transfer;
  deleted browser data or a lost source browser cannot be recovered by this
  flow.
- The transfer protocol requires pending-transfer state, matching-code UI,
  source revocation, and target authorization enforcement in the frontend and
  backend.
