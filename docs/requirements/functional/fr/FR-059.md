# FR-059: Validate And Normalize Availability Response Names

Before creating or updating an [Availability Response](../../../terminology/glossary.md#availability-response), the system shall remove control and Unicode-format characters, trim whitespace, and normalize its name to [Unicode Normalization Form C (NFC)](../../../terminology/glossary.md#unicode-normalization-form-c-nfc).

## Acceptance Criteria

- The normalized [Availability Response](../../../terminology/glossary.md#availability-response) name must be non-empty and no more than 100 code points.
- The system shall reject ObjectID-like names.
- Availability-response names compare case-sensitively after normalization.
- An [Event Guest](../../../terminology/glossary.md#event-guest) may own multiple [Availability Responses](../../../terminology/glossary.md#availability-response) for the same event; duplicate display names are not allowed.
