# FR-062: Restore Event Guest Access After Event Sign-In

For a PostgreSQL event, when an [Anonymous Event Visitor](../../../terminology/glossary.md#anonymous-event-visitor) with an active [Granted Event Visitor Control Credential](../../../terminology/glossary.md#granted-event-visitor-control-credential-granted-evcc) signs in, the system shall obtain explicit confirmation before associating the response-owning source [Event Visitor Identity](../../../terminology/glossary.md#event-visitor-identity) with the visitor's [Platform Visitor Identity](../../../terminology/glossary.md#platform-visitor-identity) for durable recovery.
It shall not substitute the current browser's [Event Visitor Identity](../../../terminology/glossary.md#event-visitor-identity) as the response owner.

On another browser, a [Platform Visitor Identity](../../../terminology/glossary.md#platform-visitor-identity) shall be able to edit every [Protected Event Response](../../../terminology/glossary.md#protected-event-response) created by an associated [Event Visitor Identity](../../../terminology/glossary.md#event-visitor-identity).
For an event not owned by that **Platform Visitor Identity**, association of a new **Event Visitor Identity** alone shall not authorize a [Protected Event Response](../../../terminology/glossary.md#protected-event-response) created by a different **Event Visitor Identity**.
MongoDB [Protected Event Response](../../../terminology/glossary.md#protected-event-response) recovery through an [Event Response Edit Credential](../../../terminology/glossary.md#event-response-edit-credential) remains unchanged.
