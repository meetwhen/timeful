# FR-121: Serve Records From A Single Authoritative Store

The system shall serve every record kind's reads and writes from exactly one authoritative store.
Core record kinds are accounts and profiles, [Timed Events](../../../terminology/glossary.md#timed-event), [Dates-Only Events](../../../terminology/glossary.md#dates-only-event), day-of-week events, availability groups, signup forms, [Event Responses](../../../terminology/glossary.md#event-response), attendees, folders, and folder membership.
Retained record kinds are [Calendar Connections](../../../terminology/glossary.md#calendar-connection), provider credentials, sub-calendars, calendar preferences, OTP challenges, and historical daily user logs.

PostgreSQL is the authoritative store for every record kind, and no legacy document or recovery source shall be read as a second authority or used to create, merge, rename, or authorize a record.
Each account reference shall resolve to exactly one account identity.
Friend requests are retired rather than stored and have no authoritative store.

Automated tests over representative records show one authoritative value per record, no duplicate account identity for a legacy account, and no record authored in two stores.
