**Failure 1 — weekly re-anchor: root cause CONFIRMED by static tracing.**
- Edit name-only of a weekly event: `NewEvent.vue` submit (L880-897) → `buildSpecificTimesEditDraft` `!specificTimesEnabled` branch (`specificTimesEditDraft.ts:119-137`) → `activeSlots = schedule.enabledSlots`.
- `schedule` comes from `buildEventEditorSchedule` whose weekly branch anchors at `Temporal.Now` (`eventEditorSchedule.ts:129-152`, `now` at L129) — so the edit PUT carries the *now*-week Mon/Wed domain, not the June-seeded anchor week of the earliest active instant.
- The server accepts it: it derives the domain from the payload's earliest active (the new actives), `active ⊆ derived` holds, 200 echo → seeded Jan actives are replaced by this week's. The spec's `savedEvent.activeSlots === <Jan seed>` assertion then fails.
- `NewGroup.vue` avoids this via `preserveExistingTimedSchedule` (L404-448) — that is why the group test (test 2 of `timed-event-weekly-firefox.spec.ts`) passed while test 1 failed.
- Both the `!specificTimesEnabled` draft branch and `eventEditorSchedule.ts` are byte-identical to `HEAD` (`git diff` empty for the builder, draft diff only touched the merge/apply branches) — the bug predates the refactor; the weekly spec last changed in `9f1e0613` "fix(app): implement ADR-012" and was likely red since then, only surfaced by this refactor's first Firefox harness run.
- Sibling bug (same root): with `specificTimesEnabled=true` on a weekly edit, `fullDaySpecificTimesSchedule` generates over the now-week (`schedule.dates`) and `mergeActiveSlotsByMembershipDay` (no membership days → projection) treats every now-week day as "added" → preserved Jan actives + ~192 now-week full-day slots → server would reject with `errActiveSlotOutsideEnabled` on grid-save. The event-aware fix (below) covers both halves.
