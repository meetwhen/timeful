## Completed Work

Investigated and fully reproduced a report that "hours collapsing doesn't work" after `fd3cb60a`
(commit `refactor: derive enabled slots instead of persisting them`). No code changed in the repo
this session; the session produced a root-cause analysis, a validated minimal fix, and an
implementation checklist. Production event under investigation: https://timeful.fun/e/82G1YPPD.

**Bug symptoms on that event (viewer in Europe/Moscow):** axis labels render `00:00, 01:00, 09:00 …`;
hours 02:00–09:00 (an inactive interior gap) are skipped entirely instead of rendering a collapsed
row, and no collapsed rows appear anywhere (end-of-day 17:00–24:00 also missing).

**Root cause (confirmed by harness, not just reading):**
- `fd3cb60a` changed the slot source of `timedGridSlotProjection` in
  `frontend/src/composables/schedule_overlap/useCalendarGrid.ts` (lines 377-381). Read-only
  (non-`SET_SPECIFIC_TIMES`) state now feeds the axis from `specificTimesViewSlots` (saved active
  subset) instead of the derived enabled domain:
  - Before: `isSpecificTimes ? specificTimesEnabledSlots : canonicalTimedSlots`
  - After: `state === SET_SPECIFIC_TIMES ? enabled : (viewSlots if non-empty) : canonical`
- Result: for events where actives do not tile the domain, the read-only axis only contains rows at
  active minutes. `buildCollapsedPageSegments` (`scheduleOverlapGridRows.ts:67`) collapses runs of
  grey rows; with no rows in the gap there is nothing to collapse, so the hours are skipped.
- The same class of regression hits canonical (working-hours) events for outer hours: at HEAD the
  interior gap still collapses (the `!isSpecificTimes` filler pass in `timedGridRows` fills
  min…max), but the start/end-of-day hours (e.g. 17:00–24:00) no longer render at all.
- The hover-over-collapsed machinery (`markCollapsedRowInactive`, `curTimeslotInactive`,
  respondent `disabled-collapsed`, clearing the hover highlight) is intact in
  `useTimedGridInteractions.ts:230` and wired in `ScheduleOverlapTimeGrid.vue:117` /
  `useScheduleOverlapController` — it is simply unreachable because no collapsed rows render.

**Validated fix (verified in a throwaway harness, not yet applied to the repo):** restore the
pre-regression read-only source in `timedGridSlotProjection`:

```ts
const slots = isSpecificTimes.value
  ? specificTimesEnabledSlots.value
  : canonicalTimedSlots.value
```

This keeps the fd3cb60a derived model (user explicitly confirmed the fix must preserve derived
enabled slots, not stored ones — it does): `specificTimesEnabledSlots` (:192) and
`canonicalTimedSlots` (:223) both come from `getEventEnabledSlots(event)` in
`frontend/src/utils/timedEventSlots.ts:440`, which derives the full civil day (00:00–24:00) per
membership day from `timedRecurrence.selectedDays`/weekly anchoring, `slotGeneration`, and
`eventTimezone`. Pre-refactor persisted `enabledSlots` were generated identically
(`fullDaySpecificTimesSchedule` with 00:00–00:00 in pre-`fd3cb60a` `specificTimesEditDraft.ts`),
which is why the restored axis matches the old day-grid behavior. No server change and no data
migration; the stale DB `enabledSlots` field remains unused.

**Harness proof (prod-faithful fixture, Moscow display):**
- HEAD: axis rows only at minutes 0–105 and 540–1005; hour labels `0:00, 1:00, 9:00…16:00`;
  `buildCollapsedPageSegments` → `[]`.
- Fix candidate: full 96-row axis 00:00–23:45; hour labels `0:00…23:00`; segments
  `[startMinutes 120, endMinutes 540]` (02:00–09:00) and `[1020, 1440]` (17:00–24:00).
- Canonical variant (same fixture, `hasSpecificTimes: false`): HEAD segments `[[120,540]]` only;
  fix candidate `[[120,540],[1020,1440]]`.

## Important Decisions

- Fix at the single projection-source point in `useCalendarGrid.ts` rather than inserting
  collapsed rows between sparse axis rows in `buildRenderedTimeGridRows`: the latter fights the
  cell mapping, grey-flag, and split-gap machinery. Restoring the enabled-domain axis restores
  all prior collapsed-hours behaviors (label per row incl. collapsed start labels, hover
  disabled semantics) with no other wiring changes.
- Chosen scope restores the full civil-day grid (00:00–24:00 with collapsed start/end bands),
  matching the user's earlier requirements ("collapse hours at the start or at the end too",
  "label for each grid row even when collapsed"). Explicitly rejected alternative: a band from
  first to last active (00:00–17:00 here) would drop the end-of-day band and contradict those
  requirements.
- `savedSpecificTimesWindow` keeps the new actives-based semantics (uses `specificTimesViewSlots`),
  which the commit changed deliberately; it only feeds seed/fallback paths and is not part of the
  collapsing bug. Leave as-is unless a visual regression shows up.
- Tests that `fd3cb60a` rewrote to assert the sparse-axis behavior must be updated back to
  collapsed-band assertions rather than deleted.
